# Frontend sources and updates

Normal builds use the checked-in frontend and do not require another Campfire
checkout, Ruby, Node, or a package registry. The application template compiler is
`tools/compile_templates.py`; edit `templates/*.html`, then run `make` and commit
the regenerated `src/templates.mojo`.

`assets/source-lock.json` inventories every served file by SHA-256 and exact
source. Unchanged compiled assets come from the C port's checked-in asset export at
`873a51f523de5a0cc235884e5725cfb5521d2027`. That export was generated from the
original/Rust frontend; [the upstream manifest](../assets/upstream-manifest.md)
records gem versions, source paths and hashes. This dependency is frontend data,
not the C application runtime. The lock captures this actual provenance rather
than pretending the compiled bundle was generated by Mojo.

Readable port-owned files live in `assets/overrides/`. File upload, clipboard,
room-list refresh and autocomplete overrides match the pinned Rust port. The
notification controller/service worker implement the matching push workflow;
the message controller includes the current Rails record-ID collision fix.
Each override's exact output and hash is in the lock. Both asset manifests are
generated from `assets/manifest.json` and must agree.

Verify without network or sibling repositories:

```sh
python3 tools/assets.py check
```

Restore every asset byte from the pinned source and checked-in overrides:

```sh
git clone https://github.com/basecamp/once-campfire-c ../once-campfire-c
python3 tools/assets.py vendor --sources ..
```

Use an existing sibling checkout if present. The vendor command reads immutable
Git objects at the locked revision, so a different checked-out branch does not
change the result. It verifies all input hashes before writing any file and does
not fetch or execute upstream code.

For an intentional frontend update, review the original/Rust source changes,
update the chosen export revision and per-file source/hash records, and update
the readable overrides. For a changed local asset, use the first eight hex digits
of its SHA-256 in the output filename, update the logical manifest and importmap,
and remove the obsolete file/lock entry. Run the vendor/check commands, regenerate
templates, then run the packaged browser and two-user identity regression gates.
Do not update golden compatibility expectations from Mojo output.

Update the corresponding package versions/notices in `licenses/manifest.json`
and retain the nested bundle notices. Update `assets/components.cdx.json` for
known nested browser package versions and run the advisory scan against it. The provenance and publication check catches
unrecorded outputs, stale manifests, changed source bytes and missing notices.
