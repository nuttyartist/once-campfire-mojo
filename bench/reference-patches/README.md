# Local durable comparison patches

These patches extend the exact cloned Rust and C repositories; they are not upstream performance figures. Apply rust-durable.patch at Rust 6dae2fd or c-durable.patch at C 873a51f using git apply, rebuild, and run the Mojo bench/run-durable.sh harness with all repositories as siblings.

The harness explicitly enables CAMPFIRE_DURABLE_JOBS=1, CAMPFIRE_SQLITE_SYNCHRONOUS=FULL, CAMPFIRE_JOB_RECEIPTS=1 and CF_JOB_WORKERS=3. Message changes and outbox admission commit atomically; workers retain failed jobs and per-recipient receipts. Rust awaits delivery completion instead of enqueueing another memory task. This contract covers the five text-message workloads. Arbitrary Rust AdHoc media futures retain their upstream queue semantics.

The benchmark requires exact acknowledged message IDs, bodies, FTS rows and three subscription receipts per message, drains every queue, and rejects drop/failure logs. Crash acceptance pauses workers before 160 posts, kills the full process group, and checks recovery and a second restart. External delivery remains at-least-once; remote acceptance and local receipt cannot form one atomic transaction.

Reference unit checks: Rust formatting and Clippy pass. The full seeded Rust suite and C bench unit suite each retain a video-preview golden-byte mismatch with pinned FFmpeg on ARM64 (11790-byte JPEG versus a 11788-byte golden). The unchanged media path in both ports gives the same mismatch; no golden or test assertion was altered. Text-workload parity, database integrity and forced-crash completion gates pass independently.

Pending claims use a partial index ordered by job ID, and lease renewal has a message lookup index. tests/durable_indexes.py checks the actual source query plans before timing, preventing backlog-wide sorting and lease scans in these comparison extensions.

The C patch also checks readiness with an indexed read before an atomic claim. Without this check, idle per-kind worker pools acquired SQLite's writer lock every 10 ms and starved actual writers. A strict log gate rejected an isolated comparison on SQLITE_BUSY even though jobs were retained. tests/durable_idle.py holds the writer lock beyond the busy timeout with an empty queue; this reproduced 16 claim failures before the fix and passes afterward. The benchmark runs this regression before timing. The eligibility read is finalized before the atomic UPDATE, which rechecks the condition against competing workers. Error logging, leases, FULL durability and completion checks are unchanged.

The preceding local reference revisions were Rust ff8fe2efa45ecbd281509cdc865acdeb11dbafcc and C 8895301 (idle-pool correction). Both patch files include all local changes relative to the upstream bases above. Rejected preliminary runs are retained separately from the completed comparison.

The byte-safety comparison exposed a C HTTP 503 under writer contention. Its request connection retained a 1-second upstream lock budget while durable workers waited 5 seconds; Rust used 5 seconds and Mojo 10. The opt-in reference patches now give application and job write connections the same 10-second budget as Mojo, preserving stock defaults outside durable mode. `tests/durable_contention.py` holds a writer lock for six seconds, then requires HTTP 200, the committed message/FTS row, and all three recipient receipts. It reproduced C 503 before the correction. The idle-worker gate now holds its empty-queue lock for 10.5 seconds. The aborted nine-run experiment is retained separately; the entire experiment restarts with the shared budget.
